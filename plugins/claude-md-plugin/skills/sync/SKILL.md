# /sync

소스코드에서 `.claude/index.md`를 자동 생성/갱신합니다.

## Triggers

- `/sync`
- `인덱스 생성`
- `reindex`

## Arguments

| 이름 | 필수 | 기본값 | 설명 |
|------|------|--------|------|
| `path` | 아니오 | `.` | 대상 경로 |
| `--all` | 아니오 | false | 전체 디렉토리 대상 (tree-parse) |
| `--p-only` | 아니오 | false | Phase 1 (P sections)만 생성, AI 요약 스킵 |
| `--check` | 아니오 | false | staleness 보고만, 생성하지 않음 |
| `--force` | 아니오 | false | 모든 대상을 stale로 처리 |

## Workflow

### 0. 초기화

```bash
CLI_PATH=$("${CLAUDE_PLUGIN_ROOT}/scripts/install-cli.sh")
TMP_DIR=".claude/tmp/${CLAUDE_SESSION_ID:+${CLAUDE_SESSION_ID}/}"
mkdir -p "$TMP_DIR"
```

### 1. 대상 해석

**--all 모드:**
```
Skill("claude-md-plugin:tree-parse", args: "{path}")
```
tree-parse 결과에서 `needs_claude_md[]` 디렉토리 목록을 대상으로 사용.

**default 모드 (단일 디렉토리):**
- `path` 인자가 있으면 해당 디렉토리
- 없으면 현재 디렉토리 (`.`)
- 디렉토리에 소스 파일이 있는지 확인 (없으면 안내 후 종료)

### 2. Staleness 검사

각 대상 디렉토리에 대해:

```bash
# index.md 존재 여부
INDEX_FILE="{dir}/.claude/index.md"

if [ ! -f "$INDEX_FILE" ]; then
  # stale: index.md 미존재
  STALE=true
else
  # mtime 비교: 소스 파일 중 index.md보다 새로운 것이 있는지
  NEWER=$(find "{dir}" -maxdepth 1 -type f \( -name "*.ts" -o -name "*.tsx" -o -name "*.js" -o -name "*.jsx" -o -name "*.py" -o -name "*.rs" -o -name "*.go" -o -name "*.java" -o -name "*.kt" \) -newer "$INDEX_FILE" | head -1)
  if [ -n "$NEWER" ]; then
    STALE=true
  else
    STALE=false
  fi
fi
```

**--force**: 모든 대상을 `STALE=true`로 처리.

**--check 모드**: staleness 결과만 보고하고 종료:
```markdown
# Sync Check Report

| 디렉토리 | 상태 |
|----------|------|
| src/auth | stale (index.md 미존재) |
| src/utils | up-to-date |
| src/api | stale (2 files newer) |

stale: 2/3, up-to-date: 1/3
```

### 3. Phase 1 (P sections) — CLI 전용

각 stale 대상에 대해 순차 실행:

```bash
# 3a. 코드 분석
$CLI_PATH analyze-code \
  --path "{dir}" \
  --output "${TMP_DIR}sync-{dir_safe}-analysis.json"

# 3b. 분석 요약 생성 (Exports, Dependencies, Contracts, Protocol)
$CLI_PATH format-analysis \
  --input "${TMP_DIR}sync-{dir_safe}-analysis.json" \
  --output "${TMP_DIR}sync-{dir_safe}-format-analysis.md"

# 3c. 바운더리 분석 (Structure용)
$CLI_PATH resolve-boundary \
  --path "{dir}" \
  --output "${TMP_DIR}sync-{dir_safe}-boundary.json"
```

**Structure 섹션 조립:**
boundary.json의 `direct_files`에서 파일명과 확장자를 추출하여 테이블 생성:

```markdown
## Structure

| File | Type |
|------|------|
| auth.ts | TypeScript |
| types.ts | TypeScript |
```

**P-only index.md 조립:**
```markdown
<!-- Auto-generated by /sync. Do not edit manually. -->
<!-- Generated: {ISO 8601 timestamp} -->

# Index: {module_name}

{format-analysis.md의 ## Exports 부분}

{format-analysis.md의 ## Dependencies 부분}

## Structure

| File | Type |
|------|------|
...

{format-analysis.md의 ## Contracts 부분, 있으면}

{format-analysis.md의 ## Protocol 부분, 있으면}
```

조립된 P-sections 결과를 `${TMP_DIR}sync-{dir_safe}-p-sections.md`에 저장.

> **Note**: `dir_safe` = dir에서 `/`를 `-`로 치환 (e.g., `src/auth` → `src-auth`)

### 4. Phase 2 (ND-D sections) — AI 요약

**--p-only이면 이 단계 스킵** → Phase 1 결과를 최종 index.md로 Write.

**P 섹션 사전 비교**: 이전 index.md가 있으면 Exports/Dependencies/Structure를 비교하여, 변경 없는 대상은 Phase 2를 스킵합니다.

Phase 2가 필요한 각 대상에 대해 (최대 3개 concurrent Task 권장):

```
Task(index-generator):
  "대상: {dir}
   analysis: ${TMP_DIR}sync-{dir_safe}-analysis.json
   format-analysis: ${TMP_DIR}sync-{dir_safe}-format-analysis.md
   p-sections: ${TMP_DIR}sync-{dir_safe}-p-sections.md
   previous: {dir}/.claude/index.md (있으면)"
```

index-generator agent가 Export Descriptions + Behavior 섹션을 추가하여 최종 index.md 생성.

### 5. 최종 보고

```markdown
# Sync Report

| 디렉토리 | Phase 1 | Phase 2 | 상태 |
|----------|---------|---------|------|
| src/auth | done | done | synced |
| src/utils | done | skipped (--p-only) | synced (P-only) |

총 {n}개 모듈 동기화 완료.
```

## DO / DON'T

**DO:**
- CLI 도구로 P sections 결정적 생성
- Phase 2는 P 변경 시에만 (이전 index.md와 비교)
- staleness 검사로 불필요한 재생성 방지
- `.claude/` 디렉토리 자동 생성

**DON'T:**
- CLAUDE.md나 DEVELOPERS.md 수정
- 소스코드 수정
- Phase 1에서 AI 사용 (결정적 CLI만)
- index.md를 수동 편집 권유

## 오류 처리

| 상황 | 대응 |
|------|------|
| CLI 빌드 실패 | install-cli.sh가 자동 빌드 |
| 소스 파일 없음 | 안내 메시지, 해당 디렉토리 스킵 |
| analyze-code 실패 | 경고, 해당 디렉토리 스킵 |
| index-generator agent 실패 | P-only 결과로 fallback |
