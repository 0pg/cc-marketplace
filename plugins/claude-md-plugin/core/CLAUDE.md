# core

## Purpose

Provides the Rust crate root for the claude-md-plugin deterministic CLI engine. This directory owns the Cargo package manifest, the compile-time code generation pipeline (`build.rs` + `schema-rules.yaml`), and orchestrates the `src/` library modules and `tests/` BDD suite into a single deployable binary (`claude-md-core`).

## Requirements

- REQ-1: The `schema-rules.yaml` file must be the single authoritative source of truth for all CLAUDE.md and DEVELOPERS.md schema validation rules; it is consumed at compile time by `build.rs` to generate Rust constants and at runtime by `validate-schema`.
- REQ-2: `build.rs` must regenerate `schema_rules.rs` whenever `schema-rules.yaml` changes, without requiring manual edits to generated code.
- REQ-3: The crate must compile with `cargo build --release` on stable Rust (edition 2021) and produce a single binary artifact used by all plugin SKILLs and Agents.
- REQ-4: All CLI subcommand implementations and BDD acceptance tests are provided by child modules — see `src/` and `tests/` for their requirements.

## Conventions

### Project Structure

```
core/
├── build.rs            — Compile-time code generation from schema-rules.yaml
├── schema-rules.yaml   — YAML SSOT for all CLAUDE.md/DEVELOPERS.md schema rules
├── Cargo.toml          — Rust crate manifest (package, dependencies, test harness)
├── src/                — Library + binary source modules (see src/CLAUDE.md)
└── tests/              — BDD acceptance tests and fixtures (see tests/CLAUDE.md)
```

### Module Boundaries

Inherits from project root. Additionally:
- `build.rs` has access only to `[build-dependencies]`; it must not import production library code.
- `schema-rules.yaml` is the only file that `build.rs` reads at compile time.

Inherits from project root.

### Coding Rules

Inherits from project root. Additionally:
- `build.rs` may use `unwrap()`/`expect()` only because compile-time failures are fatal and provide clear error messages.
- Generated `schema_rules.rs` must begin with `// Auto-generated by build.rs from schema-rules.yaml` and `// DO NOT EDIT MANUALLY`.

Inherits from project root.

## Domain Context

- The `core/` crate is the Tier 1 (deterministic) layer of the claude-md-plugin two-tier architecture; no LLM calls, network I/O, or async are permitted in production code.
- `schema-rules.yaml` drives both compile-time constants (via `build.rs`) and documentation (`references/shared/claude-md-schema.md`); changes here propagate to all consumers automatically.
- Version bumps to `Cargo.toml` must be coordinated with the plugin version in `.claude-plugin/plugin.json`.
